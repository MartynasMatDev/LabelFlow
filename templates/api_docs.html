Overview

The LabelFlow REST API lets you upload images, fetch and create annotations (bounding boxes, polygons, masks), and manage authentication tokens — all without opening the web UI. It is designed for automation scripts, dataset pipelines, and third-party integrations.

  • All endpoints live under /app/images/api/.
  • All requests and responses use application/json, except image upload, which uses multipart/form-data.
  • All endpoints are CSRF-exempt — safe to call from non-browser clients.
  • Coordinates are percentages (0–100) of the image's dimensions, not pixels.

Authentication

Most endpoints require authentication. You can authenticate in one of two ways:

  1. API Token — recommended for scripts. Obtain a token from POST /app/images/api/token/, then send it in the Authorization header: 
    Authorization: Token <your_token_here>

    Authorization: Bearer <token> is also accepted.

  2. Session cookie — automatic when you call the API from a browser already logged into LabelFlow.
One active token per user. Calling POST /app/images/api/token/ again will revoke any previously issued token. Tokens are also invalidated automatically when you change your password.
POST /app/images/api/token/

Create an API token

Exchange username and password for an API token. No authentication required.

Request body

FieldTypeRequiredDescription
usernamestringYesYour LabelFlow username
passwordstringYesYour LabelFlow password

Example

curl -X POST {{ request.scheme }}://{{ request.get_host }}/app/images/api/token/ \
  -H "Content-Type: application/json" \
  -d '{"username": "alice", "password": "s3cret"}'

Response 200 OK

{
  "token": "a1b2c3d4...64-char-hex...",
  "username": "alice"
}

Errors

StatusMeaning
400Missing username/password or invalid JSON
401Invalid credentials
DELETE /app/images/api/token/

Revoke the current token

Invalidates the token used in the Authorization header.

Example

curl -X DELETE {{ request.scheme }}://{{ request.get_host }}/app/images/api/token/ \
  -H "Authorization: Token $TOKEN"

Response 200 OK

{ "revoked": true }
GET /app/images/api/tokens/

List your active tokens

Returns metadata only. The plaintext token value is never returned after creation.

Response 200 OK

{
  "tokens": [
    { "id": 1, "created_at": "2026-05-15T09:22:10.456789Z" },
    { "id": 2, "created_at": "2026-05-14T14:15:30.123456Z" }
  ]
}
DELETE /app/images/api/tokens/<token_id>/

Revoke a specific token

Useful when revoking from a session and you don't want to invalidate the session's own token.

Response 200 OK

{ "revoked": true, "id": 42 }

Errors

StatusMeaning
401Not authenticated
404Token not found, or belongs to another user
POST /app/images/api/upload/

Upload an image to a project

Accepts a single image file via multipart/form-data. The image is normalized (RGB, ~1024px on the long edge, center-cropped to square) and stored.

Form fields

FieldTypeRequiredDescription
image_filefileYesJPG, JPEG, PNG, WEBP, BMP, or GIF. Max 20 MB.
projectintegerYesTarget project ID. You must have access to it.

Example

curl -X POST {{ request.scheme }}://{{ request.get_host }}/app/images/api/upload/ \
  -H "Authorization: Token $TOKEN" \
  -F "project=123" \
  -F "image_file=@/path/to/photo.jpg"

Response 201 Created

{
  "id": 456,
  "name": "photo.jpg",
  "url": "{{ request.scheme }}://{{ request.get_host }}/media/images/2026/05/photo.jpg",
  "project_id": 123,
  "status": "pending",
  "width": 1024,
  "height": 768,
  "file_size_bytes": 102400,
  "file_size_kb": 100.0,
  "resolution": "1024×768",
  "uploaded_at": "2026-05-16T10:30:45.123456Z",
  "uploaded_by": "alice"
}

Errors

StatusMeaning
400Missing field, unsupported file type, file too large, or invalid image
401Not authenticated
403You don't have access to the project
404Project not found
GET /app/images/api/images/<image_id>/annotations/

List annotations on an image

Returns all bounding boxes, polygons, and masks attached to an image.

Example

curl {{ request.scheme }}://{{ request.get_host }}/app/images/api/images/456/annotations/ \
  -H "Authorization: Token $TOKEN"

Response 200 OK

{
  "image_id": 456,
  "image_name": "photo.jpg",
  "status": "partial",
  "bboxes": [
    {
      "id": 10,
      "label": { "id": 5, "name": "person", "color": "#ff6b6b" },
      "x": 10.5, "y": 20.0, "width": 30.0, "height": 25.0
    }
  ],
  "polygons": [
    {
      "id": 20,
      "label": { "id": 6, "name": "tree", "color": "#51cf66" },
      "points": [
        { "x": 15.0, "y": 10.0 },
        { "x": 45.0, "y": 10.0 },
        { "x": 30.0, "y": 40.0 }
      ]
    }
  ],
  "masks": [
    {
      "id": 30,
      "label": { "id": 7, "name": "road", "color": "#868e96" }
    }
  ]
}
About the status field — "pending" means no annotations, "partial" means some, "done" means complete. Mask data is intentionally omitted from list responses to keep payloads small.
POST /app/images/api/images/<image_id>/annotations/

Create an annotation

Add a bounding box, polygon, or segmentation mask to an image. Send JSON with a type field and the shape-specific fields below.

Common fields

FieldTypeRequiredDescription
typestringYesOne of "bbox", "polygon", "mask"
label_idintegerNoID of the tag/label. Omit or send null for unlabeled.

Bounding box — type: "bbox"

FieldTypeDescription
x, ynumber (0–100)Top-left corner as % of image width/height
width, heightnumber (0–100)Size as % of image width/height
 
curl -X POST {{ request.scheme }}://{{ request.get_host }}/app/images/api/images/456/annotations/ \
  -H "Authorization: Token $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"bbox","label_id":5,"x":10.5,"y":20.0,"width":30.0,"height":25.0}'

Polygon — type: "polygon"

points: array of { "x": 0–100, "y": 0–100 } objects. Minimum 3 points required. 

curl -X POST {{ request.scheme }}://{{ request.get_host }}/app/images/api/images/456/annotations/ \
  -H "Authorization: Token $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type":"polygon",
    "label_id":6,
    "points":[{"x":15,"y":10},{"x":45,"y":10},{"x":30,"y":40}]
  }'

Mask — type: "mask"

mask_data must be a PNG data URI starting with data:image/png;base64,. 

{
  "type": "mask",
  "label_id": 7,
  "mask_data": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
}

Response 201 Created

{
  "type": "bbox",
  "annotation": {
    "id": 10,
    "label": { "id": 5, "name": "person", "color": "#ff6b6b" },
    "x": 10.5, "y": 20.0, "width": 30.0, "height": 25.0
  }
}

Errors

StatusMeaning
400Invalid JSON, unknown type, missing/invalid fields, polygon < 3 points, bad mask data, or unknown label_id
401Not authenticated
403You don't have access to this image's project
404Image not found
DELETE /app/images/api/annotations/<type>/<annotation_id>/

Delete an annotation

Where <type> is bbox, polygon, or mask.

Example

curl -X DELETE {{ request.scheme }}://{{ request.get_host }}/app/images/api/annotations/bbox/10/ \
  -H "Authorization: Token $TOKEN"

Response 200 OK

{ "deleted": true, "type": "bbox", "id": 10 }

Error format

All errors return JSON with an error field describing the problem.

{ "error": "You do not have access to this project." }

Validation errors may return an array of messages:

{ "error": ["x is required.", "width must be between 0 and 100."] }

Status codes

CodeMeaning
200OK — request succeeded
201Created — new resource created
400Bad Request — invalid input
401Unauthorized — missing or invalid auth
403Forbidden — authenticated but not permitted
404Not Found — resource doesn't exist
